# АРХИТЕКТУРНЫЙ ДОКУМЕНТ: Edge-расширение для [VK.RU](http://VK.RU) (Шаг 1)

## A. Цель

Спроектировать минимальную и современную архитектуру браузерного расширения для Microsoft Edge (Manifest V3), предназначенного для точечного взаимодействия пользователя с сущностями (персонами, сообществами) на портале `https://vk.ru/`.
Расширение не пытается модифицировать внутреннюю логику [VK.RU](http://VK.RU), а создает **собственный UI-слой** (визуальные маркеры, бейджи, цвета) поверх существующего пользовательского интерфейса, позволяя пользователю фиксировать контекстные заметки и статусы для интересующих его объектов.

## B. Границы

**Входит в скоуп:**

- Поддержка только desktop-версии Microsoft Edge.
- Работа исключительно с порталом `https://vk.ru/`.
- Использование современного стека: Manifest V3, Service Worker, Content Scripts, `chrome.contextMenus`, `chrome.storage.local`.
- Точечный сбор данных: выделение / наведение / ПКМ $\rightarrow$ идентификация $\rightarrow$ сохранение.
- Инъекция собственного слоя представления (CSS/DOM) поверх контейнеров [VK.RU](http://VK.RU).

**Не входит в скоуп:**

- Поддержка Chrome, Firefox, Safari, мобильных платформ и других доменов ([vk.com](http://vk.com), [youtube.com](http://youtube.com) и т.д.).
- Массовый автоматический парсинг, обход страниц и построение глобальной базы пользователей.
- Воссоздание CRM-логики, сложной системы тегов и диспетчеризации из старого `Context RepuTracker`.
- Написание кода адаптера (`vkru.js`) и реализации (отложено до следующих шагов).

## C. Поток данных

```text
VK.RU DOM (Пользовательский интерфейс)
       ↓
[VK.RU Adapter / Content Script]
 (Обнаружение сущности через navigation target / href / data-атрибуты)
       ↓
Нормализованный объект (ENTITY)
       ↓
Действие пользователя (ПКМ / выделение / клик по маркеру)
       ↓
[Background Service Worker]
 (Обработка команд contextMenus, маршрутизация, работа с Storage)
       ↓
[Storage / UI]
 (Сохранение записи, Popup, Диалог редактирования)
       ↓
[Собственный слой представления]
 (Инъекция CSS-классов / DOM-элементов (▲, цвет) в sourceElement)
```

## D. Ответственность каждого компонента

1. **`content.js` (Точка входа адаптера):**
   - Инициализация `MutationObserver` для отслеживания SPA-переходов и подгрузки новых элементов [VK.RU](http://VK.RU).
   - Делегирование поиска сущностей модулю `vkru.js`.
   - Перехват событий выделения текста (`selectionchange`) и контекстного меню.
   - Инъекция собственного UI-слоя (DOM-узлов и CSS-классов) поверх найденных сущностей.
2. **`adapters/vkru.js` (Адаптер обнаружения):**
   - Анализ DOM-узла на предмет наличия устойчивых признаков (ссылки, `href`, `data-*`).
   - Нормализация данных в контрактный объект `ENTITY`.
   - Абстрагирование от внутренней верстки и CSS-классов [VK.RU](http://VK.RU).
3. **`background.js` (Service Worker):**
   - Регистрация и управление пунктами `chrome.contextMenus`.
   - Взаимодействие с `chrome.storage` (чтение/запись маркеров и заметок).
   - Обмен сообщениями (Message Passing) между `content.js`, `popup` и диалогами.
4. **`ui/dialog.js` & `popup.js`:**
   - Интерфейс для выбора типа сущности, назначения маркера (треугольник, цвет), добавления примечания и даты.
5. **`styles.css`:**
   - Изолированные стили собственного слоя расширения, инжектируемые на страницу для отрисовки маркеров без конфликта со стилями VK.

## E. Контракт адаптера [VK.RU](http://VK.RU)

Адаптер возвращает стандартизированный объект, не зависящий от внутренней структуры React-компонентов VK.

```javascript
// ENTITY CONTRACT
{
    type: "PERSON" | "COMMUNITY" | "COMMENT_AUTHOR" | "POST_AUTHOR" | "OTHER",
    identity: {
        id: "string",       // Устойчивый идентификатор (например, "id123", "club456", "wall-123_456")
        url: "string",      // Нормализованный navigation target
    },
    context: {
        source: "comment" | "post" | "sidebar" | "search",
        parentPostId: "string | null",
        threadId: "string | null"
    },
    sourceElement: HTMLElement, // Ссылка на DOM-узел для привязки UI-слоя (не передается в background)
    capabilities: {
        canTag: true,
        canNote: true
    }
}
```

## F. Какие признаки считаются идентификационными

- **Navigation Target (href / URL):** Ссылка, которую браузер показывает в статусной строке или которая содержится в атрибуте `href` дочерних/родительских элементов. **\[CONFIRMED\]**
- **Структура URL:** Извлечение базового пути (например, `/id12345`, `/wall-123_456`, `/club789`) из `href` с отбрасыванием GET-параметров (`?reply=...`). **\[CONFIRMED\]**
- **Data-атрибуты:** Наличие атрибутов вида `data-post-id`, `data-author-id`, `data-id` в DOM-дереве [VK.RU](http://VK.RU). **\[HYPOTHESIS\]** — *требуется инспекция DOM для подтверждения их наличия и устойчивости.*

## G. Какие признаки являются только наблюдаемыми

- **CSS-классы верстки:** Классы вида `vkit-ewZ0L2`, `vkit-VbEObC`, `Post__author`, `ui_wall_post`. **\[OBSERVED\]** — *считаются хрупкими, подверженными минификации и изменениям. Используются только как последний резерв для поиска контейнера, но NEVER для идентификации.*
- **Текст ника / Аватар:** Отображаемое имя и URL картинки. **\[CONFIRMED\]** — *не являются уникальными и могут быть изменены пользователем.*
- **Внутренние React-ключи / Fiber-ноды:** **\[UNKNOWN\]** — *не должны использоваться архитектурой, так как требуют жесткой привязки к версии фреймворка VK.*

## H. Как архитектура защищается от динамической верстки [VK.RU](http://VK.RU)

1. **Принцип "Собственного слоя":** Расширение не модифицирует внутренние свойства или классы объектов VK. Оно добавляет соседние DOM-элементы (например, `<span class="ctx-marker">▲</span>`) или применяет собственные CSS-классы к родительским контейнерам.
2. **Делегирование и MutationObserver:** `content.js` использует `MutationObserver` для отслеживания изменений DOM (подгрузка комментариев, SPA-навигация). При появлении новых узлов адаптер заново сканирует их на наличие `identity.url` и перепривязывает сохраненные маркеры.
3. **Игнорирование визуальных классов:** Поиск контейнеров осуществляется через семантические атрибуты (`href`, `role`, `data-*`) или относительные пути от известных устойчивых точек (например, поиск ближайшей ссылки `<a>` внутри контейнера комментария).

## I. Как используется navigation target

Navigation target является **первичным и единственным надежным источником идентификации**.

1. При взаимодействии пользователя с элементом (наведение, выделение) адаптер считывает `href` ближайшей релевантной ссылки.
2. URL нормализуется: удаляются трекеры, параметры `thread`, `reply`, `from`. Оставляется семантическое ядро (например, `https://vk.ru/wall-123_456`).
3. Нормализованный URL (или извлеченный из него ID) используется как первичный ключ (Primary Key) для поиска в `chrome.storage.local`.
4. Если запись найдена, `content.js` применяет к `sourceElement` соответствующие стили из `styles.css`.

## J. Как может использоваться ПКМ/выделение

Используется штатный API `chrome.contextMenus` в связке с `selectionchange`:

1. **Сценарий:** Пользователь выделяет текст ника или поста $\rightarrow$ нажимает ПКМ $\rightarrow$ выбирает пункт *"Context: Записать сущность"*.
2. **`background.js`** перехватывает `onClick` пункта меню, запрашивает у `content.js` активный `ENTITY` (на основе текущего выделения или фокуса).
3. Открывается `dialog.html` (или Popup) с предзаполненными данными: тип, ID, контекст (где найдено).
4. Пользователь назначает маркер (тип, цвет, треугольник), добавляет примечание и сохраняет.
5. `background.js` обновляет `storage` и рассылает сообщения в `content.js` для мгновенной отрисовки маркера через собственный слой.

## K. Какие части старого расширения НЕ переносятся

- **Диспетчеризация `Handlers = new Map()`:** Старая система маршрутизации (`ranks`, `histatuses`, `setstatus`) избыточна для точечного инструмента.
- **Глобальная модель данных (users, ranks, history, events, tags):** Не переносится сложная реляционная структура. Используется плоское KV-хранилище `Map<IdentityURL, EntityRecord>`.
- **Множественные адаптеры порталов:** Файлы `ljcom.js`, `habrcom.js`, `rutube_env.js` и поддержка 6 доменов удаляются. Остается только `vkru.js`.
- **Файлы `aftershock.js`, `mutation.js`, `snettemplate.js`:** Их логика устарела и заменяется нативными API (MutationObserver, CSS-in-JS / инъекция стилей).
- **Массовый сбор:** Отключается любая логика автоматического обхода страниц и фоновой агрегации базы.
