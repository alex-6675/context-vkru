```
Edge: чистый профиль + CDP-порт 9222 + автозагрузка расширения из dist
PowerShell 7.6.5, Windows 10

$requiredPSVersion = [version]'7.6.5'
if ($PSVersionTable.PSVersion -lt $requiredPSVersion) {
    Write-Error "Требуется PowerShell $requiredPSVersion или выше"; exit 1
}
Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'

$EdgePath   = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
$ProfileDir = 'C:\Users\An\serv6675\Edgetestcontext'   # ВНЕ репо — правильно
$CdpPort    = 9222
$DistDir    = (Resolve-Path (Join-Path $PSScriptRoot '..\dist')).Path

if (-not (Test-Path $EdgePath)) { Write-Error "Не найден Edge: $EdgePath"; exit 1 }
if (-not (Test-Path (Join-Path $DistDir 'manifest.json'))) {
    Write-Error "В dist нет manifest.json — сначала выполните задачу Build."; exit 1
}
if (-not (Test-Path $ProfileDir)) {
    New-Item -ItemType Directory -Path $ProfileDir -Force | Out-Null
}
if (Get-NetTCPConnection -LocalPort $CdpPort -State Listen -ErrorAction SilentlyContinue) {
    Write-Error "Порт $CdpPort занят. Закройте ВСЕ окна Edge и повторите."; exit 1
}

$edgeArgs = @(
    "--user-data-dir=$ProfileDir",
    "--remote-debugging-port=$CdpPort",
    "--remote-debugging-address=127.0.0.1",
    "--disable-extensions-except=$DistDir",
    "--load-extension=$DistDir",
    '--no-first-run',
    '--no-default-browser-check',
    '--disable-component-update',
    '--start-maximized'
)
Start-Process -FilePath $EdgePath -ArgumentList $edgeArgs

$ok = $false
for ($i = 0; $i -lt 10; $i++) {
    Start-Sleep -Seconds 1
    try { $targets = Invoke-RestMethod -Uri "http://127.0.0.1:$CdpPort/json" -TimeoutSec 2; $ok = $true; break }
    catch { }
}
if ($ok) {
    Write-Host "Edge запущен: порт $CdpPort открыт, вкладок: $($targets.Count)" -ForegroundColor Green
    Write-Host "Расширение автозагружено из: $DistDir" -ForegroundColor Green
} else {
    Write-Error "Порт $CdpPort не ответил. Закройте все Edge и повторите."; exit 1
}
```

Как это принято в IT (простыми словами)

Связка такая: я (проектировщик) пишу задание → задание кладётся в репо файлом → Кодер читает файл, исполняет, отчитывается в тот же файл → вы тестируете → я верифицирую. Чат — для обсуждений. Репозиторий — для решений. «Кладу как попало» — нормальная болезнь первого проекта, лечится одной папкой.

Где лежат задания

Папка docs/tasks/. Один файл = одно задание. Имя: TASK-0001-короткое-имя.md. Файл состоит из двух частей: задание проектировщика (дословно) и отчёт Кодера (коммит, статус).
```

TASK-0001 — M-03r: ПКМ-изъятие ссылки (фундамент)
СТАТУС: NEW / IN WORK / DONE / BLOCKED   (пишет Кодер)

== ЗАДАНИЕ (текст проектировщика, дословно) ==

== ОТЧЁТ КОДЕРА ==
Коммит:
Статус: ...
Заметки: ...
```

Типичный коммит

Принят формат «Conventional Commits»: тип(область): текст [TASK-NNNN]. Типы: feat (новое), fix (починка), docs (документы), style (внешний вид), refactor, test, chore (инфраструктура). Правила:

одно задание = один коммит (или несколько с одним [TASK-NNNN]);
не смешивать расширение и дашборд в один коммит;
в коммите только то, что указано в задании.

Примеры под вашу текущую очередь:
```

docs: создать docs/tasks/, TASK-0001..0004
feat(ext): M-03r — ПКМ «Сохранить персонажа/сообщество», изъятие linkUrl [TASK-0001]
chore(infra): RunEdgeCdp.ps1, .gitignore, tasks/launch, opencode.jsonc [TASK-0002]
docs: AGENTS.md — Дополнение А (целостность и гейты) [TASK-0003]
style(dashboard): строгий деловой дизайн, референс Gmail [TASK-0004]
```
