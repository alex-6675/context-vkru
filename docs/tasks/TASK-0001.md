Как это принято в IT (простыми словами)

Связка такая: я (проектировщик) пишу задание → задание кладётся в репо файлом → Кодер читает файл, исполняет, отчитывается в тот же файл → вы тестируете → я верифицирую. Чат — для обсуждений. Репозиторий — для решений. «Кладу как попало» — нормальная болезнь первого проекта, лечится одной папкой.

Где лежат задания

Папка docs/tasks/. Один файл = одно задание. Имя: TASK-0001-короткое-имя.md. Файл состоит из двух частей: задание проектировщика (дословно) и отчёт Кодера (коммит, статус).
```

TASK-0001 — M-03r: ПКМ-изъятие ссылки (фундамент)
СТАТУС: NEW / IN WORK / DONE / BLOCKED   (пишет Кодер)

== ЗАДАНИЕ (текст проектировщика, дословно) ==

== ОТЧЁТ КОДЕРА ==
Коммит:
Статус: ...
Заметки: ...
```

Типичный коммит

Принят формат «Conventional Commits»: тип(область): текст [TASK-NNNN]. Типы: feat (новое), fix (починка), docs (документы), style (внешний вид), refactor, test, chore (инфраструктура). Правила:

одно задание = один коммит (или несколько с одним [TASK-NNNN]);
не смешивать расширение и дашборд в один коммит;
в коммите только то, что указано в задании.

Примеры под вашу текущую очередь:
```

docs: создать docs/tasks/, TASK-0001..0004
feat(ext): M-03r — ПКМ «Сохранить персонажа/сообщество», изъятие linkUrl [TASK-0001]
chore(infra): RunEdgeCdp.ps1, .gitignore, tasks/launch, opencode.jsonc [TASK-0002]
docs: AGENTS.md — Дополнение А (целостность и гейты) [TASK-0003]
style(dashboard): строгий деловой дизайн, референс Gmail [TASK-0004]
```
Готовый текст Кодеру (ваша просьба про дашборд, как TASK-0004)

Передайте дословно или положите файлом:
```
TASK-0004 — редизайн дашборда
ЦЕЛЬ: строгий, деловой дизайн дашборда.
Визуальный референс: дефолтный интерфейс Google Mail —
нейтральный светлый фон, плотная стандартная типографика,
обычные таблицы и списки, маленькие нейтральные статус-чипы
(зелёный/серый/красный), простая шапка-панель.

УБРАТЬ: неон, градиенты, тёмную «терминальную» эстетику,
декоративные анимации, экзотические шрифты — весь визуальный шум.

СОХРАНИТЬ БЕЗ ИЗМЕНЕНИЙ: функциональность, данные, логику шагов
v01..v15, статусы PASS/FAIL/BLOCKED/NOT TESTED, узлы Roadmap.

ФАЙЛЫ: только dashboard/src/ (стили и компоненты).
НЕ ТРОГАТЬ: EdgeExtension/, scripts/, reports/, docs/.

СБОРКА: npm run build — обязана пройти.
КОММИТ: отдельный: style(dashboard): строгий деловой дизайн,
референс Gmail [TASK-0004]
ОТЧЁТ: по форме (CHANGED FILES / BUILD / RESULT / STOP).
```
Что сделать сейчас (три шага)

Создать docs/tasks/, положить четыре файла: TASK-0001 (M-03r), TASK-0002 (инфра-пачка), TASK-0003 (Дополнение А в AGENTS.md), TASK-0004 (редизайн).
Передать Кодеру: работать только по файлам из docs/tasks/, отчитываться в них же, коммиты — в формате выше.
Мне вернуть хэши коммитов TASK-0001..0003 — я сверю raw-файлы на GitHub, затем ваш простой тест M-03r (ПКМ → скриншот).

С этого момента «как попало» закончилось: у каждого решения есть файл, у каждого файла — коммит, у каждого коммита — номер задания.

===========
node_modules в корне — НЕТ

npx -y chrome-devtools-mcp@latest не создаёт nodemodules в проекте. npx скачивает пакет в свой кэш внутри профиля пользователя (…\AppData\Local\npm-cache\npx) и запускает оттуда. В корне проекта ничего не появляется.

Единственный nodemodules в проекте — у дашборда (dashboard/nodemodules/), он там и остаётся, в git не ходит (уже в .gitignore или добавить).

ms-edgedevtools.vscode-edge-devtools — сейчас НЕТ

У вас уже два канала в браузер: attach (F5, launch.json) и MCP через SCA. Расширение Edge Devtools дало бы панель DOM/стили внутри VS Code — оно понадобится позже, на этапах визуального слоя (метки, блеклость). Сейчас не ставьте.

Рекомендуемый .vscode/settings.json
```
{
  // базовая гигиена (сохраняем из старого)
  "files.eol": "\n",
  "files.encoding": "utf8",
  "files.autoGuessEncoding": false,
  "files.trimTrailingWhitespace": true,
  "files.insertFinalNewline": true,

  // артефакты есть на диске, но не мозолят глаза и не тормозят поиск
  "files.exclude": {
    "/node_modules": true,
    "/dist": true
  },
  "search.exclude": {
    "/node_modules": true,
    "/dist": true
  },
  "files.watcherExclude": {
    "/node_modules/": true,
    "/dist/": true
  },

  // код не переформатируется сам собой (урок целостности передачи)
  "editor.formatOnSave": false,
  "prettier.requireConfig": true,

  // PowerShell
  "powershell.scriptAnalysis.enable": true
}

И добавьте .vscode/extensions.json — список «что должно стоять у любого, кто откроет проект» (норма индустрии):

{
  "recommendations": [
    "ms-vscode.powershell",
    "esbenp.prettier-vscode"
  ]
}
```
Маленькое уточнение про «одну компанию»

Мы с Кодером — не одна компания, а две отдельные LLM-линии с разными ролями (проектировщик и исполнитель). «Один офис» у нас — репозиторий: задания в docs/tasks/, коммиты с [TASK-NNNN], отчёты в тех же файлах. Теперь, когда вы это настроили, связка работает как надо.

Изменения .vscode/ (settings.json, extensions.json) закоммитьте отдельным коммитом chore(env): настройки workspace и рекомендации расширений [TASK-0005] — не смешивая с кодом расширения и дашбордом.
