# INSTRUCTION.md — ежедневный рабочий регламент · context-vkru

Уровень читателя: начальный. Всё — простыми словами.

Как пользоваться документом
Это ежедневная памятка ПОЛЬЗОВАТЕЛЯ (человека).
Фундамент — в других документах:
  - РЕГЛАМЕНТ_РАБОТ.md — процесс (этапы, сборки, PASS/FAIL);
  - docs/architecture.md — архитектура и контракты (карточка v2);
  - AGENTS.md — правила КОДЕРА (агент не проектирует, только исполняет).
При противоречии сила такая: решение проектировщика (чат + docs/tasks)
  > этот документ > всё остальное.
Чат — для обсуждений. Репозиторий — для решений.
  Важное из чата обязано оказаться в репо.

# Роли и каналы
Проектировщик (дизайн-чат): задания, решения, верификация raw на GitHub,
  приёмка хэшей.
Кодер (coder.qwen.ai / SourceCraft): исполняет задачи, выдаёт файлы
  отдельными код-блоками; сам НЕ коммитит.
Пользователь: применяет файлы в VS Code, Build, коммит, пуш, тест в Edge,
  передача хэшей, вердикт PASS/FAIL.

# Задачи и статусы
Задачи живут в docs/tasks/TASK-NNNN.md. Один файл = одна задача.
  Нумерация последовательная, без перенумеровок.
Статусы задачи: NEW → IN WORK → DONE.
Кодер работает только из задач со статусом NEW.
DONE — только после хэша коммита пользователя по этой задаче.
«Сборка зелёная у Кодера» — НЕ приёмка. Приёмка = файлы в репо
  пользователя + верификация проектировщиком.

# Коммиты
3.1. Формат: тип(область): текст [TASK-NNNN]
3.2. типы: feat (новое в расширении), fix (починка), docs (документы),
     style (внешний вид дашборда), refactor, test, chore (инфраструктура).
3.3. области: ext (EdgeExtension), dashboard, infra (scripts/запуск),
     env (.vscode), docs.
3.4. Правила:
  1. Одна задача = один коммит (или несколько с одним [TASK-NNNN]).
  2. НЕ смешивать области: ext ≠ dashboard ≠ docs ≠ infra.
  3. Не коммитить: node_modules/, dist/, профиль браузера, *.log (.gitignore).
  4. Хэш появляется только после пуша; записать в файл задачи
     и передать проектировщику.
  5. Чисто документный коммит без задачи может идти без [TASK-NNNN].
3.5. Эталонные примеры:
  feat(ext): v05r — база, карточка v2, дедуп [TASK-0009]
  fix(dashboard): завершение ремонта, data-модули [TASK-0007]
  chore(infra): RunEdgeCdp.ps1, .gitignore, tasks/launch, opencode.jsonc [TASK-0002]
  chore(env): настройки workspace и рекомендации расширений [TASK-0005]
  docs: гигиена docs/tasks — хэши, формат [TASK-0008]
  style(dashboard): строгий деловой дизайн, референс Gmail [TASK-0004]
  docs: INSTRUCTION.md — ежедневный рабочий регламент
3.6. Рабочая ветка: main-qwenv03. Пуш: git push origin2 main-qwenv03.

Передача кода без порчи
Не копировать код из рендер-вью чата: markdown съедает подчёркивания.
   Копировать из код-блоков raw или из файла в VS Code.
Файл = ровно одна копия кода. Запрещены: строки «修改后», пути файлов
   текстом, вторые копии, дописанные в конец.
Селекторы и regex с «_» — в коде только через String.fromCharCode(95).
Самопроверка после применения:
   - Get-ChildItem dashboard\src, EdgeExtension -Recurse | Select-String '修改后' → 0;
   - панель Problems (Ctrl+Shift+M) → 0 ошибок;
   - `npm run build` (внутри dashboard/) → проходит.
manifest version и CTX_BUILD поднимать строго по заданию;
   оба значения — в отчёт.

# Сборка и артефакты
Расширение: исходники в EdgeExtension/, артефакт в dist/.
  Edge загружается из dist/. Сборка — scripts/Build.ps1 (задача VS Code «Build»).
Дашборд: все npm-команды ТОЛЬКО внутри папки dashboard/
  (монорепозиторий: у каждого приложения свой package.json).
Node.js 22 LTS (зафиксировано в .nvmrc). PowerShell 7.6.5.

# Тесты и статусы
Статусы только: PASS / FAIL / BLOCKED / NOT TESTED.
PASS ставит ТОЛЬКО пользователь.
Расширение: консоль F12 на vk.ru, фильтр CTX; консоль SW —
  edge://extensions → service worker.
Дашборд: `npm run build` + один взгляд.
При FAIL работа остаётся ВНУТРИ задачи; не перескакивать.

# Запуск окружения
7.1. Edge с чистым профилем: scripts/run-edge-vk-test.ps1
     (или RunEdgeCdp.ps1 — с портом 9222 для CDP). Пути к Edge и профилю
     зашиты в начале файла — править там. Если Windows запрещает запуск:
     Set-ExecutionPolicy -Scope Process Bypass (один раз, для терминала).
7.2. Расширение: edge://extensions → «Режим разработчика» →
     «Загрузить распакованное расширение» → папка dist/
     (после Build — кнопка Reload ⟳ на карточке).
7.3. Дашборд: cd dashboard → npm install (один раз) →
     npm run dev (http://localhost:5173) либо npm run build + npm run preview.

# Где искать, если сломалось
Расширение: карточка в edge://extensions (ошибки, версия = версии задания).
Нет строк в консоли: фильтр CTX; вкладка перезагружена после Reload.
Дашборд не собирается: вывод npm run build; «нет файла» = файл не
  закоммичен (см. §4).
Подозрение на порчу: самопроверка §4.4.
