## Аннотация: `scripts/run-edge-vk-test.ps1`

> Уровень читателя: **нулевой** — объясняем всё простыми словами.

### Что это за файл?

Это маленькая **программа-помощник для тестирования**. Она открывает браузер
Microsoft Edge в **отдельном чистом профиле**, чтобы вы могли проверять
расширение, не смешивая его с вашими личными данными (вкладками, паролями,
закладками).

### Зачем это нужно?

Когда вы разрабатываете расширение для браузера, его удобно тестировать
«с нуля». Чистый профиль — это как «новый браузер» без ваших настроек:
так видно только то, что делает расширение, и ничего лишнего не мешает.

### Как это работает простыми словами

Скрипт выполняет четыре шага:

1. **Проверяет версию PowerShell.** Скрипту нужна версия **7.6.4 или выше**.
   Если у вас старая версия, он останавливается и пишет об этом.
   *PowerShell — это программа для выполнения команд в Windows.*

2. **Проверяет, где установлен Edge.** Ищет файл браузера по стандартному пути
   `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`.
   Если Edge не найден — останавливается и предупреждает.

3. **Создаёт отдельную папку-профиль**, если её ещё нет. В этой папке Edge будет
   хранить данные «чистого» браузера. Если папки нет — скрипт создаёт её сам.

4. **Запускает Edge** с чистой папкой-профилем и несколькими полезными флагами:
   - открывает окно во весь экран;
   - пропускает первое приветствие и лишние проверки;
   - не обновляет браузер автоматически.

### Что вы увидите после запуска

- В консоли (терминале) появятся строчки, где написан путь к Edge и к папке профиля.
- Откроется новое окно Edge — это и есть «чистый» браузер.
- В конце появится подсказка (жёлтым цветом), что расширение нужно **загрузить вручную**:
  откройте в адресной строке `edge://extensions` и добавьте папку `EdgeExtension`.

### Как запустить скрипт

```powershell
# run-edge-vk-test.ps1 — запуск Edge в чистом профиле для теста расширения
# Запуск: cd путь-до-папки-scripts; .\run-edge-vk-test.ps1
cd путь-до-папки-scripts
.\run-edge-vk-test.ps1
```

> ⚠️ Если Windows запрещает запуск, введите один раз:
> `Set-ExecutionPolicy -Scope Process Bypass`
> Это разрешит запуск только для текущей сессии терминала.

### Важные примечания

- В скрипте **зашиты конкретные пути** (к Edge и к папке профиля). Если на вашем
  компьютере Edge установлен в другое место или вы хотите другую папку профиля —
  эти строки нужно поправить в самом начале файла.
- Папка профиля в примере: `C:\Users\An\serv6675\Edge_test_context\`.
- Скрипт **не устанавливает и не загружает** расширение автоматически —
  это делается вручную через `edge://extensions` (включите «Режим разработчика»).

## Раздел: `dashboard/` — веб-приложение-рабочий лист процесса

> Уровень читателя: **нулевой** — объясняем всё простыми словами.

### Что это за папка?

Папка `dashboard/` — это **отдельное веб-приложение проекта** (по лучшим практикам IT
называется **дашборд** — «рабочий лист / панель процесса»). Оно построено на связке
**React + Vite + TypeScript** и служит визуальным инструментом команды:
показывает аудит соответствия, дорожную карту сборок v_01–v_15 и рабочий лист
**текущего шага** (листинги файлов, критерии теста, фиксация вердикта PASS/FAIL).

> С каждым шагом разработки дашборд обновляется: появляется новый вид доски
> (например, на v_02 — схема диагностического канала PING/PONG). Это **не меняет**
> версию Node.js (остаётся 22 LTS) и не требует установки новых инструментов —
> нужна лишь **пересборка** (запуск `npm run dev` или `npm run build`), чтобы увидеть
> актуальный вид. Для новичка: просто выполните команды ниже — Node уже настроен.

**Важно:** это приложение **не входит** в корень расширения `EdgeExtension/`,
который загружается в Edge. Дашборд — это вспомогательный инструмент разработки,
он не требуется для работы самого расширения.

### ⚠️ Главное правило: команды запускаются ВНУТРИ папки `dashboard/`

Все команды npm для дашборда выполняются **только внутри папки `dashboard/`**.
Перед любой командой сначала перейдите в неё:

```powershell
cd путь-до-папки-dashboard
```

> Почему это важно? В проекте **несколько независимых приложений**, у каждого
> своя папка и свой файл `package.json` со своими зависимостями
> (например, у `dashboard/` — React/Vite, а у расширения `EdgeExtension/` —
> вообще нет Node-зависимостей). Такая структура типична для **монорепозитория**:
> в одном репозитории хранится несколько независимых приложений
> (`dashboard`, `EdgeExtension`, `docs` и т.д.), и команды нужно запускать именно
> в папке того приложения, с которым вы работаете. Запуск npm-команды «сверху»
> (из корня репозитория) приведёт к ошибке — там нет `package.json` для дашборда.

### Какая нужна версия Node.js

Для сборки дашборда нужен **Node.js 22 LTS** (на вашей машине установлен `22.23.2` —
подходит). Версия зафиксирована в файле `.nvmrc` в корне репозитория.

### Шаг 1. Установка зависимостей (один раз)

```powershell
# dashboard — установка зависимостей (выполняется внутри папки dashboard/)
# Запуск: cd путь-до-папки-dashboard; npm install
cd путь-до-папки-dashboard
npm install
```

Эта команда скачает все нужные библиотеки (React, Vite и др.) в папку `node_modules`.
Делается один раз после клонирования.

### Шаг 2. Запуск в режиме разработки (с автообновлением)

```powershell
# dashboard — запуск режима разработки (выполняется внутри папки dashboard/)
# Запуск: cd путь-до-папки-dashboard; npm run dev
cd путь-до-папки-dashboard
npm run dev
```

После запуска в консоли появится локальный адрес, например `http://localhost:5173/`.
Откройте его в браузере — увидите дашборд. При изменении файлов страница
обновляется автоматически.

### Шаг 3. Продакшен-сборка (статичные файлы)

```powershell
# dashboard — продакшен-сборка (выполняется внутри папки dashboard/)
# Запуск: cd путь-до-папки-dashboard; npm run build
cd путь-до-папки-dashboard
npm run build
```

Соберёт оптимизированные файлы в папку `dashboard/dist/`. Их можно открыть через:

```powershell
# dashboard — предпросмотр собранной версии (выполняется внутри папки dashboard/)
# Запуск: cd путь-до-папки-dashboard; npm run preview
cd путь-до-папки-dashboard
npm run preview
```

### Короткая шпаргалка

Все команды запускаются **только внутри папки `dashboard/`**.
Сначала выполните `cd путь-до-папки-dashboard`, затем одну из команд:

| Команда | Что делает |
| --- | --- |
| `npm install` | Устанавливает зависимости (один раз) |
| `npm run dev` | Запускает дашборд локально с автообновлением |
| `npm run build` | Собирает продакшен-версию в `dashboard/dist/` |
| `npm run preview` | Показывает собранную версию локально |

### Важные примечания

- **Всегда сначала переходите в папку `dashboard/`** (`cd путь-до-папки-dashboard`),
  только потом выполняйте npm-команду.
- Устанавливайте зависимости командой `npm install` (не вручную).
- Дашборд требует Node.js 22; для расширения `EdgeExtension/` Node не нужен.
- После появления нового шага (новой сборки) просто перезапустите `npm run dev`
  или выполните `npm run build` — Node и зависимости менять не нужно.
- Остановить запущенный `npm run dev` — нажмите `Ctrl + C` в терминале.
