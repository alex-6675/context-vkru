# SPLIT.md v4 — регламент раздвоения: приоритеты, слои, протокол выхода
Редакция: проектировщик (секция IT). Заменяет v1–v3 и предварительную
редакцию (коммит 30e2b5c, issue #23).

## 0. Ветви и приоритеты
- mem-2026 — ПРИОРИТЕТНАЯ ветвь: довести до состояния передачи
  (музей / кадетский класс — определиться). Имя «reputracker» не закрепляется.
- «Мои записки» (личная «вторая память», продуктовая линия context-vkru) —
  развиваются позднее; готовятся под более массивную глобальную задачу.
  До точки раздвоения по ней делается только то, что нужно ядру (v07f, v_08r).
- Точка раздвоения НЕ отменяет ни один проект — она расставляет приоритеты.

## 1. Суть и точка раздвоения
- Два продукта на общем ядре. Ядро = код + регламенты; ветви = цели, данные, сценарии.
- Точка: PASS v07f + завершение v_08r (слияние/каноникализация).
- В момент принятия точки проектировщик выдаёт «бумажку» — протокол SPLIT-0
  (состав ядра, provenance-хэш, составы ветвей, порядок работ);
  коммитится как docs/SPLIT-0.md. До точки действует настоящий документ (v4).

## 2. Слои mem-2026 (в порядке приоритета)
1. БАЗА ОБЩЕНИЯ — первоочередное. Всё для контакта через соцсети (VK/OK)
   поверх общего ядра. Массовый пользователь — ЮНИОР: простые статусы,
   регламент-памятка, шаблоны; коммит джуниора верифицирует старший (клеймо).
2. БАЗА ПАВШИХ — уже есть: классификаторы, системно сложенные карточки;
   источники obd-memorial/ЦАМО (приказ №181); поля «кого известить»/«адрес»;
   списки выгружены (Yandex Disk), структуры баз — .csv.
   Трек А «ПЛИТЫ»: 600+ с документальным подтверждением на «Копечь»;
   статусы documented → approved → engraved; экспорт списков на
   изготовление (CSV/печать).
3. ПРЕДСТАВИТЕЛЬСТВО В СЕТИ — место осмысляется. На представительстве —
   обязательный чёткий раздел: «Согласование с Минобороны РФ о нанесении
   гравировок согласно данным, опубликованным в ЦАМО и на площадках,
   им подчинённых». Образец дизайна — немецкая реализация (личный контакт
   с со-руководителем). До решения о месте слой НЕ развивается.

## 3. Треки (из предварительной редакции — в силе)
А «ПЛИТЫ» · Б «ПОИСК» (волонтёры; «могут быть причастны» = потомки;
изъятие в соцсетях поверх ядра) · С «ПЕРЕДАЧА» (музей/кадетский класс;
джуниоры ищут контакты).

## 4. Слой данных mem-2026 (НЕ тащить в личную линию)
- soldier: {имя, место, даты, source, реквизиты фонд/опись/дело/страница,
  notify, address, plate}.
- descendant: живая карточка v3 + «может быть причастен»
  (гипотеза/подтверждено/отклонено) + evidence; track: volunteer/junior/school; mentor.
- connection: soldier ↔ descendant; evidence = документ + ссылка.
- Пересечение ветвей — ТОЛЬКО через данные: живая персона с меткой
  «может быть причастен» → экспорт vCard 3.0 / CSV → «Мост поколений».
  Базы не смешиваются (разные ключи storage, профили, репо).

## 5. Общее ядро (донор — context-vkru до точки)
normalize.js (vk/ok/dzen, id, reply), storage.js (карточка v3),
messaging.js, изъятие (ПКМ → CAPTURED), маркировка (ctx-*), регламенты.
После точки — копия в mem-2026 sync-коммитом с provenance-хэшем;
фиксы ядра — только у донора, одним sync-коммитом. K-OK (адаптер ok.ru) — после SPLIT-0.

## 6. Джуниор (массовый пользователь) и наставничество
- Порог входа: простые статусы, памятка, шаблоны.
- Коммит джуниора = заявка; верификация старшего = клеймо доказательства.
- Признание: имя джуниора рядом с именем бойца — стенд музея,
  плита «восстановлено таким-то».

## 7. Этический контур
- Массового сбора нет: только точечное изъятие (Решение №2).
- Живые: никакой публикации/экспорта без решения.
- Боец: источник + реквизиты + автор коммита обязательны.
- Согласование с Минобороны — только через официальный раздел представительства.

## 8. Протокол покидания ветки (проектировщик, данный диалог)
- Проектировщик покидает ветку, выдав SPLIT.md v4 (этот документ) и HANDOVER.md.
- Новый диалог: «прочитай docs/HANDOVER.md и docs/SPLIT.md и продолжай
  с точки сохранения».
- В точке после v_08r новый диалог выдаёт бумажку SPLIT-0 (docs/SPLIT-0.md)
  и продолжает руководство секцией IT mem-2026.
- Данная ветка остаётся архивом решений №1–6 и r-серии (v03r–v07r).
