# TEST · v_01 · Контрольный каркас

## 1. Предусловия

- Microsoft Edge (Desktop), Windows 10/11.
- Папка `EdgeExtension/` на диске; файл `manifest.json` в её корне.
- `edge://extensions` → «Режим разработчика» включён.
- Расширение «Context VK.RU 0.0.1» загружено как распакованное, в карточке нет красных ошибок.

## 2. Действия

1. В карточке расширения открыть «Service Worker» (ссылка в карточке) — посмотреть консоль SW.
2. Открыть новую вкладку → `https://vk.ru/`.
3. DevTools (F12) → вкладка **Console** (контекст: страница, не расширение).
4. Обновить страницу (F5) и повторить шаг 3.
5. Для контроля открыть любой другой домен (например `example.com`) — строки `[CTX v_01]` там быть не должно.

## 3. Ожидаемый результат (PASS-критерии)

- В консоли Service Worker строка: `[CTX v_01] service worker started`.
- В консоли страницы `vk.ru` строка: `[CTX v_01] content script active on vk.ru — path: /...`.
- Строка появляется и после обновления страницы (F5).
- На других доменах строки нет; вёрстка `vk.ru` визуально не изменилась.

## 4. Признаки FAIL

- Ошибка загрузки манифеста / отсутствие расширения в списке.
- В SW-консоли ошибки (красные) — приложить текст к RESULT.md.
- На `vk.ru` нет строки `[CTX v_01] ...` (проверить `matches` и режим разработчика).

## 5. RESULT

Фиксация — в `reports/v_01/RESULT.md`. При **FAIL** остаёмся внутри v_01 (§4, §5.1):
исправляем и повторяем тест. Переход к v_02 (PING/PONG) — только после **PASS**.
